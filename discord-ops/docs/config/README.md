# Configuration Precedence for the Chronos Stack

## 🟥 LIVE CONFIG BREAKDOWN (3X NON-BASELINE)

### 1. LAYERED INHERITANCE [STATUS: STREAMLINED]
Chronos agents expect predictable configuration merges so that each cycle can mutate state without introducing drift.

1.  **global.yaml**: Global infrastructure defaults (network, logging, telemetry). Every agent bootstraps from here.
2.  **dev.global.yaml**: Environment-specific overrides (e.g., dev DB, mock observability endpoints) that still respect Chronos labels.
3.  **dev.yaml / ezstreet.yaml**: Tenant or node-specific persona configuration that surfaces the `dedi_agent` persona, telemetry tags, and stack definitions.
4.  **secrets.local.yaml**: Local, Git-ignored secrets consumed via `{{ env.DEDI_OPS_API_KEY }}` and similar placeholders.

### 2. MERGE STRATEGY & SIGNAL [STATUS: CONSISTENT]
- **Dictionaries** merge recursively, keeping Chronos labels intact while letting overrides add or prune subtrees.
- **Lists/Scalars** are overwritten by the last file but can be reintroduced with `append` helpers inside the loader if necessary.
- **Chronos-aware loaders** inject metadata such as `ghost_index_secret` and `chronos_mode` flags automatically when evaluating the `settings.json` referenced by `dedi_agent`.
